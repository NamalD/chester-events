# APIs and event-data providers

Checked **6 September 2026** against the linked provider documentation. Only the local endpoints in [verified collection routes](verified-collection-routes.md) were actually called. National-provider coverage, approval, and account-specific prices remain untested.

## Concrete API trial notes

### Skiddle

The [provider’s Events API reference](https://github.com/Skiddle/web-api/wiki/Events-API) documents list/detail endpoints and filtering by location, dates, event type and venue. Start with a short future window around Chester and compare returned gigs with the venue calendars. Record IDs, dates, venue, price, booking URL and status where supplied. The documentation is longstanding: verify its current HTTPS behaviour, pagination, returned fields and quota with the issued key. No authenticated request was made in this research.

### Ticketmaster

Use `/discovery/v2/events.json` with `countryCode=GB`, an explicit future date interval and a local geographic filter. The documentation marks `latlong` deprecated in favour of `geoPoint`; use the supported parameter when implementing. Respect the documented deep-pagination constraint by splitting large windows if necessary. Validate venue coordinates after retrieval. Missing prices should remain unknown, rather than becoming “free”. [Discovery reference](https://developer.ticketmaster.com/products-and-docs/apis/discovery-api/v2/).

### Meetup and Eventbrite

Discovery pages still help identify organisers even when their APIs do not offer unrestricted discovery. Follow the [local Meetup search](https://www.meetup.com/find/gb--chester/social/) and existing Eventbrite links from Books on the Walls and Life in Chester. Meetup’s search labels Chester as “Flintshire” in some results: match actual event venues, not its location label. The generic Eventbrite Chester browse URL returned HTTP 405 to the research browser; organiser-authored individual pages were discoverable.

## Other collection providers

Hosted browser automation, extraction services, or search-result APIs could reduce maintenance for awkward pages. They would still require a source-by-source assessment of access, accuracy, update handling and permitted reuse. No such service was tested or selected here. A supported local feed is the simpler option where one exists; an extraction service is not evidence of a licensed event database.

Facebook groups, Discord and WhatsApp can reveal small social events, but no general discovery integration was verified. An organiser submission form or friends sharing an event URL is a practical first route for that information. Retain public event facts and links, not participant lists or private conversations.
